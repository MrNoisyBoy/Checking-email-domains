# 📧 Email Domain & SMTP Verification Tool

Инструмент для проверки валидности email-адресов через MX-записи DNS и SMTP-handshake. Позволяет определить, существует ли домен, настроен ли на нем почтовый сервер и принимает ли он письма для указанного ящика.

## 🚀 Возможности

- ✅ Проверка синтаксиса email-адреса
- 🔍 Получение и анализ MX-записей домена
- 📡 SMTP-handshake (проверка существования ящика без отправки письма)
- 📊 Цветной вывод результатов в консоль
- 📦 Пакетная проверка нескольких адресов
- 🔧 Настраиваемый таймаут и email отправителя
- 📋 Вывод в формате JSON для интеграции с другими системами

## 📋 Требования

- Python 3.7+
- Установленные зависимости:
  - dnspython

```bash

```

Или через менеджер пакетов:
```bash

```

## 🔧 Использование

### Базовый запуск
```bash
python eeeemail.py email@example.com
```

### Проверка нескольких адресов
```bash
python eeeemail.py user1@gmail.com user2@yandex.ru user3@mail.ru
```

### Дополнительные параметры

| Параметр | Описание | Пример |
|----------|----------|--------|
| `--sender`, `-s` | Email отправителя для SMTP-handshake | `--sender verify@mydomain.com` |
| `--timeout`, `-t` | Таймаут соединения (секунды) | `--timeout 15` |
| `--verbose`, `-v` | Подробный вывод SMTP-диалога | `--verbose` |
| `--json`, `-j` | Вывод в формате JSON | `--json` |

### Примеры использования

**Проверка с подробным выводом:**
```bash
python eeeemail.py test@gmail.com --verbose
```

**Увеличенный таймаут для медленных серверов:**
```bash
python eeeemail.py test@corporatemail.com --timeout 30
```

**Вывод результатов в JSON:**
```bash
python eeeemail.py test@gmail.com test@yandex.ru --json
```

**Комбинация параметров:**
```bash
python eeeemail.py test@gmail.com test@outlook.com --verbose --timeout 20 --sender verify@mydomain.com
```

**Пакетная проверка из файла (PowerShell):**
```bash
python eeeemail.py (Get-Content emails.txt)
```

## 📊 Результаты проверки

### Статусы и их значения

| Статус | Описание | Цвет |
|--------|----------|------|
| `VALID` | Email валиден (SMTP код 250) | ✅ Зеленый |
| `DOMAIN_NOT_FOUND` | Домен не существует (NXDOMAIN) | ❌ Красный |
| `NO_MX_RECORDS` | Нет MX-записей | ⚠️ Желтый |
| `INVALID_SYNTAX` | Неверный формат email | ❌ Красный |
| `INVALID_RECIPIENT` | Ящик не существует | ❌ Красный |
| `SMTP_ERROR` | Ошибка SMTP соединения | ⚠️ Желтый |
| `UNCERTAIN` | Неоднозначный результат | ❓ Синий |
| `ERROR` | Критическая ошибка | ❌ Красный |

### Пример вывода

```
======================================================================
EMAIL                          СТАТУС                    ДЕТАЛИ
======================================================================
user@gmail.com                 ✗ ЯЩИК НЕ СУЩЕСТВУЕТ       Ящик не существует (SMTP: 550 - 5.1.1)
admin@yandex.ru                ✓ ДОМЕН ВАЛИДЕН            Email существует (SMTP: 250)
test@outlook.com               ? НЕОДНОЗНАЧНО             Невозможно верифицировать (SMTP: 252)
======================================================================

Итого: 3 проверено, 1 валидных
```

## 🔬 Как это работает

1. **Синтаксическая проверка**: Проверяет соответствие email стандартному формату (регулярное выражение)

2. **DNS-запросы**: Получает MX-записи домена через DNS
   - Если MX-записей нет, проверяет существование домена (A-запись)

3. **SMTP-handshake** (самая важная часть):
   - Подключается к MX-серверу (порт 25 или 587)
   - Отправляет HELO/EHLO
   - Отправляет MAIL FROM (с указанным отправителем)
   - Отправляет RCPT TO (проверяемый email)
   - Анализирует код ответа:
     - `250` - ящик существует
     - `550` - ящик не существует
     - `252` - сервер не дает точного ответа
     - Другие коды - различные состояния

## ⚠️ Важные замечания

1. **Gmail и другие крупные провайдеры** могут отвечать "ящик не существует" для существующих адресов из соображений приватности

2. **Некоторые почтовые серверы** всегда отвечают "OK" (250) для всех получателей (catch-all), чтобы не раскрывать информацию о пользователях

3. **Анти-spam меры** могут блокировать частые проверки с одного IP

4. **SMTP-проверка не отправляет письма**, только устанавливает соединение и проверяет получателя

## 🐛 Возможные проблемы и решения

### Ошибка "No module named 'dns'"
```bash
pip install dnspython
```

### Таймаут при проверке
```bash
python eeeemail.py test@slow-server.com --timeout 30
```

### Блокировка провайдером
Попробуйте использовать другой email отправителя:
```bash
python eeeemail.py test@gmail.com --sender different@example.com
```
